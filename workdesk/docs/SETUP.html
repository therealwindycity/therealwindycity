What WorkDesk actually is

One ranked board for the work you can actually take, fed from the two platforms you already use.

WorkDesk merges Field Nation and WorkMarket listings into a single feed, scores each one against your base location, pay floor, skills and radius, and keeps track of what you did with it — saved, applied, won, lost, ignored. Everything lives in your browser. There is no WorkDesk account and no WorkDesk server.

It does three things that neither platform does on its own:

  • One board. Both platforms side by side, deduplicated, sorted by a score that is explained on every card.
  • Net $/hr, not posted pay. A $340 flat job with a posted 6-hour window is compared honestly against a $51/hr job, after the platform's fee.
  • Distance from your base. Not from wherever the platform guessed. A 1,467-city coordinate table runs offline, so distance is computed in the browser with no map API key.

The honest limits

Read this once and the rest of the guide will make sense.

Neither platform gives technicians an API.

Field Nation's REST API is the Client (buyer) API. Its published prerequisites are an active Buyer account, a signed integration contract, and credentials issued by Field Nation. There is no provider/technician-side endpoint for browsing available work orders.

WorkMarket's Open API is aimed at client companies — creating and managing assignments, labour pools, webhooks, bulk upload. There is no public contributor-side API for browsing available assignments.

So there is no key for you to paste, and no button WorkDesk could press to make one appear. Anyone who tells you otherwise is selling something.

Why the Sidekick exists instead.

You are already logged in and already looking at these listings in your own browser. The Sidekick is a userscript that runs inside your own session and hands what your browser already downloaded to WorkDesk. No credentials are read, stored, or transmitted, and nothing is fetched that your browsing did not already request.

WorkDesk never submits an application for you.

Both platforms prohibit automated session activity, and a bot-signed application is worse than no application. WorkDesk copies your pitch, opens the real work order in a new tab, and tracks the outcome. You press submit.

1 · Install the Sidekick

About five minutes. This is the only part that touches your browser.

1

Install a userscript manager

Tampermonkey is the recommended one — it is on the Chrome Web Store, Firefox Add-ons, Safari's App Store and the Edge Add-ons store. Violentmonkey and Greasemonkey also work.

2

Add the Sidekick

Open the Tampermonkey dashboard → Utilities → Install from URL, and paste:

…/workdesk/sidekick/workdesk-sidekick.user.js

Or simply open the userscript file in a new tab — Tampermonkey intercepts .user.js URLs and offers to install it.

Full detail, including what each permission is for: sidekick/install.md.

3

Point it at your WorkDesk URL

Click the Tampermonkey icon → ⚡ WorkDesk settings. The default board URL is this site. If you spin WorkDesk off into your own repo (see the last section), change it there once.

4

Confirm the handshake

Reload WorkDesk. Within a few seconds the setup pill in the top bar turns green for the Sidekick step, because the userscript checks in with a version stamp. That check-in is all WorkDesk needs to know it is installed and reachable.

What the Sidekick will and will not do

Will: watch the network responses and rendered cards on pages you open, on *.fieldnation.com and *.workmarket.com; hand those captures to WorkDesk; optionally fill your pitch into a text box when you click ⚡ Fill my pitch.

Will not: read or store passwords or cookies; submit an application; call an endpoint your browsing did not already call; send anything to anyone but your own WorkDesk board; phone home.

2 · Set your base & pay floor

Until this is right, every distance and $/hr number on the board is a guess.

Open ⋯ → Guided setup wizard → Set your base, or press ? and choose My profile.

FieldWhat it does
Home baseYour city/state, or exact coordinates. Look up from city/state uses the built-in 1,467-city table — no map key, works offline. 📍 Use my location asks the browser, and nothing is sent anywhere.
Pay floor / targetFloor = the net $/hr below which a job is nearly always skipped. Target = what makes you say yes. Both drive the biggest weight in the score.
Ideal / max milesInside ideal miles scores a full 1.0. Past max miles it drops to 0.05.
SkillsMatched against the title, description, work types and requirements of each order.
Platform feeThe haircut taken before net $/hr. Field Nation defaults to 10%; WorkMarket to 0% because it is usually bill-rate rather than fee-deducted. Change it if your contract says otherwise.
Typical job lengthUsed only when a flat-fee posting has no window posted, so a $340 job can still be compared against hourly ones.

Press Check it. The wizard verifies the step and only advances when it really passes — and when it fails it tells you exactly which field to fix.

3 · Get your first real orders

Open Field Nation's available-work page or WorkMarket's assignments list in another tab. The Sidekick pill shows a live count of what it captured. Then:

  • Send to WorkDesk — pushes to an already-open WorkDesk tab instantly, or opens one.
  • Auto-send — sends every capture as you browse, so the board fills itself.
  • Copy code — a compact sync code for the clipboard, for when pop-ups are blocked.
  • Teach me the page — if a platform redesigns and the count stays at 0, click this on a listing card. It learns your selector and remembers it. This is the escape hatch that keeps a UI change from being a dead end.

Three other ways in, if the Sidekick is not an option right now:

  • Paste text. Copy a listing (or twenty) straight off the page and paste it into ⋯ → Import work orders. The parser finds city/state, pay, dates and skills in free text.
  • Drop a CSV or JSON file. Drag it anywhere on the board. A spreadsheet you keep yourself works fine.
  • Paste a sync code from another device.

Nothing loaded? Look at the sample board first.

The board auto-loads 24 sample orders on a first run so you can see how ranking behaves before any real data arrives. Clear them from ⋯ → Import work orders once your real feed is flowing.

4 · Write your pitch once

Open ⋯ → Pitch templates. Tokens are filled per job at apply time:

{first_name} {last_name} {phone} {email} {certifications} {experience_years} {tools} {vehicle}
{company} {title} {city} {state} {home_city} {home_state} {distance} {drive_time} {start_day}
{pay} {hourly} {skills} {platform} {order_id} {completed_jobs}

Keep several templates — a short one for retail reset work, a detailed one for structured cabling — and pick per job from the dropdown in the drawer. If a token cannot be filled, the drawer shows a red badge listing exactly which ones, so you never paste {first_name} into a real application by accident.

The Sidekick also injects a ⚡ Fill my pitch button beside every text box on the platform's own page, so you can fill your template without leaving the platform. It types into the box and stops. It never presses submit.

5 · Apply (you always press submit)

Press Apply + copy pitch on a card, or in the drawer. WorkDesk then:

  1. fills your template for that specific order and copies it to the clipboard;
  2. opens the real work order in a new tab — a deep link like app.fieldnation.com/workorder/8841207, not a search page;
  3. moves the order to your Applied tab with a timestamp and the exact pitch you sent;
  4. tells you plainly: paste and press submit there.

Afterwards, record the outcome — 🏆 Won, ✗ Lost / no reply, or ↩ Reopen. Outcomes feed the buyer-history component of the score, so buyers who actually award you work drift up the board over time and buyers who never reply drift down.

Follow up on your own terms

The drawer has a notes box and a follow-up list. WorkDesk will remind you; it will never message a buyer for you.

Syncing between devices

WorkDesk stores everything in IndexedDB in the browser that holds it. To move data between a laptop and a phone, use ⋯ → Sync & relay:

ModeHow it worksNeeds
Sync codeA gzipped, checksummed WD1-… string. Copy on one device, paste on the other. Typically under 1 KB per order.nothing
Same browser, two tabspostMessage with a one-time nonce. Instant, automatic.nothing
ntfy.sh relayThe Sidekick pushes captures to a private ntfy.sh topic; WorkDesk polls that topic. Free, no account.a topic name you invent
Gist relayThe Sidekick PATCHes a secret Gist; WorkDesk reads it.a fine-grained PAT with the gist scope only
Custom URLAny endpoint you control that accepts and returns JSON.your own endpoint
Committed feedWorkDesk also reads data/feed.json from this repo if something has written it. See the API poller.repo secrets, set by you

Never put a platform password in a relay.

A relay carries work orders. A Gist token, if you use one, must be a fine-grained PAT scoped to gist and nothing else. It is stored in your browser only, and WorkDesk's own export strips it before writing a backup file.

The API poller (and why it is off)

This is the part people go looking for. Here is exactly what it is, what it needs, and why it does nothing today.

The repo ships workdesk/worker/poll.py and a GitHub Actions workflow (.github/workflows/workdesk-poll.yml) that runs it on a schedule and commits workdesk/data/feed.json. WorkDesk reads that file on boot, so a poller that works would mean the board fills itself even when your browser is closed.

It is dormant on purpose.

With provider/technician accounts there are no credentials to give it. The workflow runs green with no secrets set, writes nothing, and costs nothing. It is scaffolding for the day you have buyer-side access — not a broken feature.

Path A — Field Nation Client (buyer) API

Only available if you hold, or work for someone who holds, a Field Nation Buyer account with a signed integration contract. Field Nation issues the credentials; they are not self-service. The API uses an OAuth 2.0 password grant that returns a token valid for one hour and issues no refresh token, and the token must be appended as a query parameter on every request.

FIELD_NATION_CLIENT_ID=...
FIELD_NATION_CLIENT_SECRET=...
FIELD_NATION_USERNAME=...
FIELD_NATION_PASSWORD=...
FIELD_NATION_BASE_URL=https://api.fieldnation.com/api/rest/v2
# sandbox instead: https://api-sandbox.fndev.net/api/rest/v2

Path B — WorkMarket API

Company-side. Needs an API token and secret issued to a client company, and works against api.dev.workmarket.com in their documented samples.

WORKMARKET_TOKEN=...
WORKMARKET_SECRET=...
WORKMARKET_BASE_URL=https://api.workmarket.com/v2
WORKMARKET_LIST_PATH=/assignments/list_updated
WORKMARKET_DETAIL_PATH=/assignments/{id}

Turning it on, if you ever get credentials

  1. In the repo: Settings → Secrets and variables → Actions → New repository secret, one per variable above. Secrets can only be added through the web UI — a workflow cannot set its own secrets.
  2. Run python3 workdesk/worker/poll.py check locally to confirm which credentials are present. It prints MISSING for anything absent and exits 0 either way, so it is safe to run blind.
  3. Run python3 workdesk/worker/poll.py selftest — it exercises the extraction and feed-writing path against three built-in sample orders with no network access. This passes today, offline.
  4. Trigger workdesk-poll from the Actions tab with sandbox: true to hit a sandbox environment first.
  5. The cron is 23 */4 * * * — four times a day, off the top of the hour so it does not pile up with everyone else's 0 * * * *. Edit that line in the workflow to change the cadence.

Why the poller is not the recommended path even when it works

A buyer-side API shows the work orders you posted, not the ones available to you as a technician. For a provider, the Sidekick reading your own logged-in session is the only thing that actually sees available work. The poller earns its place when you start buying work as well as selling it.

Phone notifications

⋯ → Notifications asks the browser for permission and then fires a desktop/phone notification when a newly arrived order clears your minimum score, minimum pay and maximum miles. Settings:

  • Minimum WorkScore to notify on (default 70).
  • Minimum pay, and maximum miles.
  • Quiet hours, so a 2 a.m. relay sync does not wake you.

Notifications only fire for orders that arrive while the board is open, or on a manual refresh — a static site has no server to push from. For alerts that reach you with the board closed, use the ntfy relay: the Sidekick can push straight to a topic on ntfy.sh, and the ntfy phone app delivers it even when nothing is open.

The poller workflow also supports an NTFY_TOPIC secret — set it and every successful poll can ping your phone.

Privacy & credentials

  • No account, no server, no telemetry. WorkDesk is static files. Your orders, settings, pitches and outcomes live in IndexedDB in your own browser.
  • No credentials, ever. WorkDesk never asks for a Field Nation or WorkMarket password, and has no field to put one in. The Sidekick never reads cookies or password fields.
  • Exports are scrubbed. A backup file strips any relay token before it is written.
  • Diagnostics are scrubbed. The "advance the program" report contains settings shapes, counts and error messages — never passwords, tokens, or the contents of your work orders.
  • Deleting is deleting. ⋯ → Import work orders → Clear the board removes every stored order. Clearing your browser's site data removes everything including settings.

Respect the platforms' terms

Both platforms restrict automated access to their services. WorkDesk deliberately stays on the right side of that: it reads what your own browsing already loaded, it never logs in as you, it never submits anything, and it applies no more often than you click. Keep it that way — do not wire it up to hammer an endpoint on a timer.

Troubleshooting

Start in-app: ⋯ → Diagnostics runs sixteen self-tests against your actual browser — storage backend, compression support, the city table, a geocode, a haversine check, three pay parses, both platform adapters, CSV, pasted text, a sync-code round trip, dedupe stability, the relay and the committed feed. Anything red there is the thing to fix first.

The full symptom-by-symptom table is in TROUBLESHOOTING.md. The short version:

SymptomFix
Sidekick pill shows 0 on a platform pageThe page markup changed. Click the listing card, then Teach me the page. Or reload with the pill's Rescan.
Nothing arrives in WorkDeskPop-ups blocked. Use Copy code in the pill and paste it into ⋯ → Import work orders.
Board is empty on first loadThe sample file did not load. Check ⋯ → Diagnostics; if the site is served over file://, use a local web server instead.
Distances look wrongYour base is unset, or a listing posted only a state. State-only rows are badged rough and scored down, never silently trusted.
$/hr missing on a jobNo window and no duration posted. Set Typical job length in your profile, or open the order and read the posted text.
An order mapped wrongIn the drawer press 🩺 Not mapped right?. It copies a diagnostic and opens a pre-filled issue.
Data disappearedBrowser cleared site data, or you are in a private window. Restore from ⋯ → Export & backup if you took one.

Moving WorkDesk to your own repo

WorkDesk currently lives in workdesk/ inside the therealwindycity/therealwindycity repo, which is primarily a civic-transparency project. If you want it standalone — its own URL, its own issue tracker, its own Actions history — the repo ships a script for exactly that:

cd workdesk
./spin-off.sh --help
./spin-off.sh --owner YOUR_GITHUB_USERNAME --repo workdesk

It copies the app into a clean directory, initialises a fresh git history, rewrites the Sidekick's default board URL, generates the Pages and poller workflows for the new repo, and prints the two commands to run to create and push it. It does not need to guess anything about your account and it does not touch this repo.

After the spin-off, change one thing in the Sidekick: ⚡ WorkDesk settings → Board URL.

And turning Pages on here

For this repo: Settings → Pages → Source: GitHub Actions. That is a one-click setting that only a repository admin can change through the web UI — the workflow file .github/workflows/workdesk-pages.yml is already in place and will publish WorkDesk at the site root with the existing civic ledger preserved under /ledger/.
